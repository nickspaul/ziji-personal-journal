# 使用说明

[返回项目首页](../README.md)

自记是一款在本机运行的个人记录工具，使用 Spring Boot、Vue 3 和 MySQL。它支持生活日志、全局待办、身体测量和行为记录，并提供搜索、投入时间汇总、费用、趋势和数据管理。

1. 启动与解锁

    双击项目根目录的 [start.cmd](../start.cmd)。启动完成后，浏览器会打开 [自记本机页面](http://127.0.0.1:17890)。日常使用不需要分别启动前端和后端。

    首次打开时，设置自己的本地口令，至少 8 个字符。之后用这个口令解锁。页面提供隐私遮挡和立即锁定，连续 15 分钟无操作会自动锁定。遮挡只改变页面显示，不会加密数据库或导出的文件。

    应用和独立数据库都只监听本机地址。页面不会发布到公网，也不会自动同步到其他设备。正常记录可以离线进行；主动更新商品资料和首次下载构建依赖时需要联网。

2. 设置种类与单价

    进入“种类与单价”，手动添加常用香烟、酒品，或选择“查找商品资料”，核对品牌、具体型号、容量、酒精度及来源后导入。同品牌不同规格应分别建档。录入行为时也能直接新增种类，保存后返回原来的表单并选中它。

    内置参考目录目前有 18 条商品资料，覆盖范围有限。默认检索使用本地目录；明确选择联网更新时，才会访问支持的商品来源。查不到的商品可以手动添加。参考价会随渠道、时间和规格变化，导入后应核对实际包装与购买价。

    每个种类自带单价。香烟填写每包价格与每包根数；酒品填写每瓶价格、容量和酒精度。导入的参考价需要核对后确认；选择参考单价时，费用会标为估算。旧资料尚未确认价格也可以先记录用量，对应费用显示待补价格。

    吸烟费用＝每包单价 ÷ 每包根数 × 本次根数；饮酒费用＝每瓶单价 × 本人饮用量 ÷ 每瓶容量。无需填写购买流水。详细表单仍可覆盖本次采用价，香烟按每根、酒品按每瓶填写。别人提供的烟，个人费用记为零。

    新增烟酒记录时，先选择这次使用的种类，表单会显示单价、规格和费用预览。确认种类单价后，有依据的历史缺失费用会自动补齐；已有费用保留当时采用的价格，后续改价不影响它们。补价也会在应用启动时检查，重复启动不产生无变化的记录。未选种类显示“待选种类”，新旧规格不一致时显示“待核对规格”。

3. 日常记录

    首页默认显示近 7 天，也可切换到近 30 天，两个范围都包含今天。选择“累计”后，顶部显示从第一笔行为记录到今天的总量。下方的“全部历史趋势”覆盖同一段时间，折线上的点表示当天的数量。记录跨度超过 731 天时按月汇总，超过 30 年时按年汇总。

    在日历中选一天，可以查看当天的吸烟、饮酒、私人记录和烟酒估算费用。累计视图里翻月时，当月的明细和饮酒关联会随之更新，折线图始终显示全部历史。当天没有记录时计为 0，缺少价格或用量的记录会提示待补。

    | 记录 | 操作与统计口径 |
    | --- | --- |
    | 吸烟 | 首页点“记吸烟”打开表单，选择种类、填写根数后保存；可补充时间、来源和备注。后台自动计算费用。 |
    | 饮酒 | 新建一次饮酒场次，再添加其中各酒品。按瓶数输入时填写本人分量比例；按毫升输入时填写本人实际喝下的量。两种方式不会重复累计。混饮分别添加明细。 |
    | 私人行为 | 首页点“＋自慰”或“＋性生活”记一次。点编辑图标可补记日期、次数和感受。两类记录都可核对饮酒关联。旧版记录归为自慰，可在行为记录中修改类型。 |

    吸烟与私人记录保存后提供撤销。补记过去的行为时，可以选“大概时间”并填写日期和约几点，也可以只记日期；记得具体时间时再切换。饮酒明细默认沿用场次结束时间，没填结束时间则沿用开始时间，也能为某种酒单独设置时间。缺少价格、容量或酒精度的记录保留未知，不按零处理。旧购买流水仍可在“数据管理”中查看和编辑，新记录计费不采用购买流水金额。

    在“日常记账”点“记一笔”，填写实际收付金额、日期和类别。用“日／月／年”切换账期，收入、支出、结余和分类排行按所选日期汇总。年视图点月份进入月历，月历点日期查看当天流水。在日视图补记时，表单默认使用正在查看的日期。遇到和上次相同的交易，可在流水右侧点“再记一笔”，修改日期或金额后保存。买烟酒时可以记一笔实付金额，随后录入用量只更新首页的估算费用。

    页头的“导出近 30 天”会下载一份 Markdown 文件，包含今天及之前 29 天的收支、日志、待办、吸烟、饮酒和身体测量。点右侧箭头可以改起止日期、勾选私人记录或切换到 JSON。下载的文件包含所选记录的备注，可先在本机查看，再自行决定是否交给 AI。

    未记录的日期在图表和统计中自动按 0 计算，不需要每天确认。补记后，对应日期和累计值会自动更新。已经记录了行为但缺少价格、容量或酒精度时，缺项仍显示待补，不按 0 处理。未来日期保持空白；身体测量也不会补成 0。

    “个人设置”可选择只记录或温和提醒，并设置安静时段与每日提醒上限。应用关闭时不会发送提醒。

4. 生活日志与待办

    打开侧栏“生活日志”，可以按天回看、搜索记录或管理待办。“吃饭、工作、上课、外出、出差”按钮会打开相应的录入表单；日期和一句话即可保存，详细内容、同行人、地点、标签及关联任务按需填写。标签和姓名输入后按回车添加，也可以选用已有内容。

    事后补记按实际发生日期保存。时间可只记日期、选择时段，或填写具体起止时间。跨日出差填写起止日期，只保存一条记录，在涉及的每一天都能查到。没有生活记录的日期显示空白，不会自动生成经历；未来安排放在待办中。

    搜索覆盖标题、正文、标签、同行人和地点。点击 `#出差` 等标签可以直接查找；搜索框中的 `#出差` 精确匹配标签，含空格的标签可写成 `#"项目 A"`。筛选支持日期、类别、人员、地点和多标签组合，常用条件可固定到页顶。事项列表按记录分页，“匹配日期”按全部结果去重列出日期，方便查找哪天出过差。每页可选 20 或 50 条。

    “全局待办”默认显示所有日期的未完成事项，包含暂缓的任务。切换日志日期不会隐藏过去安排或未安排日期的待办。安排日期与截止日期均可不填；未完成列表优先显示较早截止的任务。“完成历史”按实际完成日期倒序排列，可筛选日期范围，回看结果和累计投入。重新打开任务会清除本次完成日期，已有进展和操作历史保留。

    展开待办后，点击“记工作”或“记学习”即可录入关联日志，也可以在日常记录中选择已有任务。支持补记已完成任务的进展。填写完整起止时间时自动计算时长；只记得用了多久时，可以直接填分钟或小时。累计投入汇总该任务全部关联日志，同一任务内重叠的具体时间会去重；手填时长单独累加，未填时长的日志显示“待补”，不按零计算。详情中可以逐条查看、编辑关联记录。

    记生活时可以直接点选同行人和标签，也可以输入新名字。在“生活日志 → 同行人与标签”里可以提前添加名称、改名、合并重名或删除。改名和删除前，会列出用过这个名称的每条记录，包括回收站里的记录。逐条选择保留旧名、换成新名或移除后，再点确认。选择保留的记录仍能按旧名搜到。

    日志和待办支持编辑、移入回收站、恢复和导出筛选结果，也包含在完整备份中。关闭录入窗口可以保留草稿，锁定或刷新页面后会清除草稿。

    此模块使用日志和待办两张业务表。手填时长保存在日志的一列中，累计投入查询时计算。标签、同行人随记录保存，不另建人物、餐饮、课程或项目数据库。新记录采用独立分页查询，不随原首页一次加载。

    **一句话补记**可以从文字中识别日期、时段、同行人、地点和本人付款金额。例如“昨晚和小林在东门吃烧烤，我付了 86 元”会生成日志和餐饮支出两张草稿。可以改字段、取消其中一张，再保存。写“一共 86 元”时，自己付的金额需另外确认。

    **回顾共同经历**时，点日志中的同行人，或在“同行人与标签”中点姓名旁的“回顾”。地点旁的数字是提到它的共同日志条数。“约个下次”会打开待办草稿。“翻一条旧日记”只从生活日志取材，“结伴外出”取填写了同行人的餐饮、社交和出行记录。

    **行程花费**列出同期支出和日志。勾选车票、住宿等实际属于这次行程的流水，逐笔标为自费、待报销或已报销，再保存。报销状态按整笔金额计算。行程实付汇总已勾选的金额，修改标记不会再记一笔支出。

    **固定扣款**在日常记账里，列出从今天起七天内应付的账单和仍未确认的旧账单。每月按设定日提示，短月取月底。“已付款”按实际付款日期记入账本，已经手动录入的可选“跳过本期”。系统认出连续三个月相似的流水后，会列出原付款日期供你决定是否建立规则。

    **饮酒和吸烟日期对照**在统计分析里。每组的占比等于有对应行为记录的天数除以该组的全部天数。场次或饮用明细落在某天，这一天就算饮酒日，跨夜场次只在开始日增加一次场数。聚餐可以由“聚餐”标签或有同行人的餐饮日志识别，出差按“出差”标签识别。未记聚餐的日子可能有漏记，可以点开日期核对。

5. 身体数据、趋势与计算边界

    打开侧栏“身体数据”，填写测量日期和本次体重、身高、体脂率或腰围。只填测到的项目即可；新记录可以沿用上次的身高、年龄和模型性别参数，页面会标明来源日期，体重和体脂率留给本次填写。每次测量保留为独立记录，历史表支持编辑、移入回收站和恢复。

    卡片分别显示每项最近一次有效测量，并注明日期。同一天有多笔时，按录入顺序取最后一笔有效值；趋势图可切换最近 30、90、180 天或全部记录。BMI 只用同一笔记录的身高和体重计算：体重（kg）÷ 身高（m）²。体脂率由自己填写，不从 BMI 推算；BMI 也不能单独判断健康状况。[计算说明：CDC](https://www.cdc.gov/bmi/about/)

    酒精估算优先采用饮酒时或之前的有效身体测量；没有可用资料时，可以采用饮酒后 30 天内已经测得的最近资料，并标注为近似。这个期限是应用的资料选取规则，不表示身体在这段时间内没有变化。不同日期的身高、体重不会被悄悄拼成一条测量。

    “酒精估算与计算依据”按整小时展示模型时长。大概时间采用前后各 1 小时的录入范围，只记日期时采用当天可能时段。这些输入范围用于构造情景，不是医学保证。近期缺少酒品明细或身体资料时，会列出对应记录和补充按钮；较早的缺项单独列为待补，不再让整个面板一直停在“资料不足”。最近一次饮酒附近 72 小时只决定待补资料的展示范围，不是代谢界限；更早的已知剂量仍参与连续计算，未知剂量保留提示。

    仪表盘和“统计分析”显示按用量计算的烟酒费用、纯酒精量及折合 42 度白酒的毫升数。换算公式为：纯酒精克数 ÷（0.789 × 0.42）。例如，500 ml、5% vol 的啤酒折合约 59.5 ml 的 42 度白酒；这个换算只比较酒精量。资料不全时标明已知部分。

    烟盒成分按检测口径分组查看。包装标示值乘以根数只作标签值汇总，不代表人体实际吸收量或体内残留量。

    酒精估算采用带来源和版本的简化模型情景，并展示时间范围与假设。个体差异、未记下的饮酒、时间或身体资料缺失都会限制结果。模型给出的接近零值时间不是可靠的个人清零时间，不能证明已经清醒，也不能用于判断何时能驾驶。

    首页分别显示饮酒与吸烟、私人行为的关联条数、关联根数或次数、占比以及待判断条数。占比的分母是当前日期范围内全部已记录的对应行为条数，包含信息不足的记录。明细可查看发生时间、相关饮酒场次和判断依据。

    关联区分饮酒期间、模型估算时段、近期有饮酒记录和信息不足。没有找到饮酒记录不等于没有喝酒；时间重合也不能说明因果。私人记录可以人工更正，系统判断与更正说明会一并保留。修改或补录饮酒后，关联会重新计算。

6. 管理与修正数据

    “行为记录”按吸烟、饮酒场次、酒品明细和私人记录分类。“数据管理”使用分组目录，集中管理行为、日志、全局待办、商品单价和身体测量。每类数据顶部说明用途，点击“用途与规则”可查看计算和使用说明。

    表格支持中文名称、选项、日期和备注搜索，多个关键词用空格隔开。可以点击列名排序、调整显示列和每页条数；筛选或翻页后清空已选项，批量操作仅针对本页选择。导出结果包含当前筛选的全部记录和字段，不限于当前页。

    点击每条记录的详情按钮，可查看中文字段、保存时采用的价格与规格，以及费用、酒精量、BMI 等计算依据。原始数据折叠保留。新增、编辑、回收站、恢复和操作历史继续可用；金额和计算快照由后端生成，不能直接当作普通字段改写。日志和待办沿用各自的检索与分页功能。

    “参考资料”中的健康参考说明用于统计分析页的文字展示，不是个人体检资料。价格历史用于来源追溯，现行单价仍到商品中设置。“兼容数据”仅保留旧版购买流水。

    每日完整度和个人目标已移除，相关表与接口不再存在。未记录日期仍按 0 统计，正常记录、费用和趋势不受影响。导入含这两项的旧备份时，预览会说明将跳过的条数，其他有效记录继续校验和恢复；新备份不再导出这两个集合。升级前请备份数据库，升级后的迁移会删除这两张旧表。

    自动补价只补缺失费用和必要的计价依据，原始数量、时间、酒精度及烟草成分保持不变。已知历史费用需要修正时，使用“预览历史重算”，核对前后值后再更新；内容没有变化的记录不会重复更新或新增审计。“价格历史”用于查阅价格来源，当前采用的单价在“种类与单价”中维护。有关联记录的商品通常应先停用，避免失去历史依据。

    数据保存复用现有商品和行为表，不生成每日零值记录或额外费用表。保存商品时按类别保留适用参数，避免把每瓶容量存入香烟资料、把每包根数存入酒品资料；备份导入保留原始内容。

7. 备份与恢复

    在“个人设置”的“备份与恢复”中导出完整 JSON 备份。文件包含个人记录、备注、计算快照和操作历史，应保存在只有自己可以访问的位置。CSV 用于查看或整理，不能代替完整 JSON 备份。

    导入备份后先查看校验结果，再确认合并。恢复前，应用会自动保存一份当前状态的备份。恢复采用合并策略：同 ID 的本机记录保留，导入备份中的新 ID；当前设置优先，不会用旧备份直接覆盖已经存在的记录。存在校验错误时不会开始导入。

    完整备份不包含解锁口令。迁移到全新环境时，需要在新环境设置本地口令。应用有业务数据并保持运行时，还会按日保存本机自动备份；应用停止期间不执行备份。

8. 关闭、数据位置与重建

    关闭浏览器后，后台服务仍会运行。结束使用时，双击 [stop.cmd](../stop.cmd)，停止自记服务及项目独立 MySQL。再次使用时运行 `start.cmd`。

    | 位置 | 内容 |
    | --- | --- |
    | `.local/mysql/data` | 项目独立 MySQL 的实际数据文件，正式数据库名为 `ziji`。 |
    | `.local/app/backups` | 正式环境的自动备份和恢复前备份。 |
    | `.local/app/server.log`、`.local/app/error.log` | 正式应用启动与运行日志。 |
    | `.local/mysql/server.log` | 项目独立数据库日志。 |
    | `.local/runtime.json` | 本机连接配置和数据库凭据，不应公开或随源码分享。 |
    | `.local/qa` | 验证环境文件；测试数据库 `ziji_qa` 与正式数据库 `ziji` 分开。 |

    独立 MySQL 使用 `127.0.0.1:13316`，不会使用你其他项目的数据库目录。`.local` 包含实际数据与配置，不是可以随意删除的缓存目录。日常备份优先使用应用内导出；不要在数据库运行时直接复制数据文件作为备份。

    修改源代码后，先运行 `stop.cmd`，再双击 [rebuild.cmd](../rebuild.cmd)。构建会检查前端、运行后端测试并重新打包；成功后再运行 `start.cmd`。本机需要能找到 Java 17、MySQL 8 的命令；重新构建还需要 Node.js、npm 和 Maven。

    如果页面无法连接，先运行 `start.cmd` 并等待启动完成。启动窗口报错时，按提示查看应用或数据库日志。端口占用、命令未找到或磁盘权限问题应先排查，不要删除 `.local` 来尝试修复。
