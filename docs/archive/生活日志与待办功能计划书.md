自记：生活日志与待办功能计划书

日期：2026 年 10 月 26 日 · 版本：方案稿 v1

新增一个侧栏页面“生活日志”，用于回看每天做过什么，也能继续跟进没做完的工作。页面内提供“按天回看”“搜索记录”“待办”三个视图。这里将“加个分页”理解为增加独立功能页面，同时为记录列表提供真正的分页。

沿用现有 Spring Boot、Vue 3、MySQL 和本机运行方式。生活记录、同行人、工作内容和搜索均在本机处理。此次交付为计划书，尚未修改程序和数据库。

1. 页面与日常使用

   侧栏在“日常概览”附近增加“生活日志”。默认打开今天，顶栏只保留日期、前后一天、回到今天、搜索、“记一件事”和“添加待办”。下方显示一周日期条，方便切到昨天补记；月历作为日期选择器展开。

   桌面宽屏左侧显示当天记录，右侧显示当天安排及仍需跟进的待办。窄屏上下排列。沿用现有深色、紧凑卡片风格，减少欢迎横幅和大数字占用。卡片先显示时段、事情摘要和标签，详细内容按需展开。

   当天没有记录时显示“这一天还没有生活记录，可以之后补记”。记录条数可以显示 0；不会据此写入“没吃饭”“没上课”“没工作”。原有行为统计的未记录计零规则继续使用，生活日志中只保存实际填写的内容。

   回看 10 月 21 日的日视图示例，以下均为虚构内容：

   | 时段 | 记录摘要 | 可展开的信息 |
   | --- | --- | --- |
   | 上午 | 高等数学：导数与微分 | 地点：教学楼；标签：高等数学 |
   | 中午 | 和小王吃牛肉面 | 地点：学校东门；具体吃的内容、感受 |
   | 下午 | 修改项目 A 的登录接口 | 已完成接口，联调待继续；关联任务：登录功能联调 |
   | 晚上 | 和小李看电影 | 地点、电影名；标签：朋友、外出 |
   | 持续事项 | 10 月 20—22 日杭州出差 | 只保存一条，涉及的各天均能看到 |

2. 记录内容与快捷录入

   一条日志最少只填日期和一句话，例如“晚上和小张吃火锅”。日期默认采用正在查看的那一天，避免在昨天的页面补记时误存为今天。

   | 内容 | 设计 |
   | --- | --- |
   | 做了什么 | 必填的一句话，作为卡片摘要 |
   | 发生日期 | 必填，支持补记；跨日事项可填结束日期 |
   | 时段 | 可选，支持只记日期、常用时段、具体时间 |
   | 分类 | 生活、餐饮、工作、学习、出行、社交、其他；可选 |
   | 详细内容 | 自由文字，记录饭菜、课程内容、工作过程及结果 |
   | 和谁 | 可选，可填多个人；支持昵称 |
   | 地点 | 可选，自由输入并提示历史常用值 |
   | 标签 | 可选，可多选，也能现场创建 |
   | 关联待办 | 可选，用于记录某项工作的实际进展 |

   提供“吃饭、工作、上课、外出、出差、普通记录”几个快捷入口。它们调整表单提示、预选分类，不建立不同的数据系统。比如“吃饭”提示吃了什么、和谁、在哪里；“上课”提示课程和学了什么；“工作”提示完成了什么、还差什么。

   一次“出差时和同事吃饭”可以用一条餐饮日志加上“出差”标签表达。出差本身另有一条持续事项时，餐饮日志描述的是其中一次实际活动，两者各有用途。

   常用人员、地点、课程标签从已有记录中提示，点选后才填入本次记录。复制旧记录时必须检查日期和参与人，不自动将上次同行人认定为本次同行人。昵称不同的人名先按原文保存，不擅自把“小张”和“张三”合并。

   表单支持键盘快速保存、保存后再记一条，以及当前解锁期间的临时草稿。离开未保存的表单时提醒；锁定后清除内存中的草稿，不把生活内容长期写入浏览器存储。

3. 时间规则

   默认适应事后记录，填写“下午”就可以保存。

   | 方式 | 例子 | 保存与展示规则 |
   | --- | --- | --- |
   | 只记日期 | 10 月 26 日出门办事 | 进入“时间未细分”，不伪造 00:00 的实际发生时间 |
   | 常用时段 | 上午上课、晚上聚餐 | 保存时段标签，不把“晚上”换成一个准确时刻 |
   | 具体时间 | 14:00 开始；或 14:00—15:30 | 起止时间按填写内容保存，结束时间可留空 |
   | 跨日事项 | 10 月 20—22 日出差 | 保存起止日期，涉及日期内都可回看和搜索 |

   常用时段提供凌晨、早晨、上午、中午、下午、晚上。选择时段的记录不计算精确时长；时间线中的位置只是排列方式。只有用户填写了完整、准确的起止时间，才展示由两者相减得到的时长，时长不额外存一份。

   允许时间重叠。例如出差期间同时上课、开会、吃饭都合理。第一版不把这些时长简单相加成“全天利用率”，也不要求把一天填满。

   跨午夜的具体时间要求明确结束日期，避免把次日凌晨误作当天凌晨。按天查看时，跨日事项单独放在“持续事项”，当天的具体活动按时段排列，未细分时间的记录单独归组。

   发生日期与录入时间分别保留。今天补记上周五的聚餐，应在上周五出现；搜索与日历按发生日期处理。日期边界统一使用应用的北京时间。未来的安排可以添加为待办；若实际日志填到了未来，保存前提示核对日期或改为安排。

   正在进行的出差只记录已经发生的日期范围，可随进展延长到今天。预计返程日写入安排或说明，实际结束后再补结束日期，避免将未来几天提前算作出差经历。

4. 标签与一键查找

   标签适合表达跨越不同分类的主题，例如“出差”“项目 A”“客户拜访”“高等数学”“朋友”。分类用于日常归类，标签用于按主题回看。

   标签输入支持补全、回车创建和多选。去掉首尾空格、可选的前缀 #，同一条记录内去重；英文大小写按统一规则匹配，保留清楚的显示名称。

   点击一条日志里的“出差”标签，立即打开相关记录。允许把常用标签或筛选组合固定在页面顶部，例如“出差记录”“项目 A”“未完成工作”，以后一次点击就能进入。固定项保存在现有偏好设置中。

   标签管理提供查看使用情况、改名和合并。改名、合并前展示涉及的记录数量，在一次事务中更新实际受影响的日志和任务；名称变化不会复制记录。移除标签只改标签，不删除对应日志。

   第一版不自动推断同义词。“出差”和“差旅”先视作不同标签，用户可以主动合并。没有使用标签的旧内容，仍能通过文字搜索找到。

5. 搜索结果怎样回答问题

   普通关键词搜索覆盖摘要、详细内容、人员、地点和标签。输入“出差”是文字包含搜索；点击标签或输入“#出差”是标签精确筛选。多个关键词默认要求全部出现，允许出现在不同字段中；多个标签可以选择“全部符合”或“任一符合”。不同种类的筛选条件组合使用。

   | 想查的内容 | 使用方式 | 结果 |
   | --- | --- | --- |
   | 我在哪几天出差了 | 点击固定标签“出差”，切到“匹配日期” | 去重后的日期、日期范围和对应事项 |
   | 我和小王什么时候吃过饭 | 分类选餐饮，人员选小王 | 聚餐日期、吃的内容和地点 |
   | 这个月做了哪些工作 | 分类选工作，日期范围选本月 | 实际工作记录，按发生日期排列 |
   | 项目 A 做到哪里了 | 搜索项目名或点“项目 A”标签 | 工作日志，以及单独标注的相关待办入口 |
   | 上过什么课 | 分类选学习，搜索课程名称 | 上课日期、课程内容及备注 |
   | 还有哪些工作没做 | 打开待办，筛选未完成和工作主题 | 待开始、进行中的任务，另可展开暂缓项 |

   搜索页提供关键词、日期范围、分类、标签、人员及地点筛选。默认搜索生活日志；切到任务结果时显示状态，并明确日期指的是安排、截止还是实际完成日期。两类结果不混成一份“已经做过”的记录。

   点击“出差”后，结果提供“事项列表”和“匹配日期”两种查看方式。一条 10 月 20—22 日的出差，在事项列表只出现一次；匹配日期可以列出这三天。同一天有多条带“出差”标签的记录，日期数量仍只计一天。筛选 10 月 21 日，也能找到这条跨日记录。

   搜索结果显示匹配片段，点开能跳到相应日期并定位记录。跨日事项从筛选日期或所选命中日期进入。返回后保留搜索词、筛选条件和页码。

   列表默认每页 20 条，可选 50 条；筛选变化时回到第一页。后端返回当前页和匹配总数，日期数量基于完整筛选结果去重，不从当前页条数推算。排序以发生日期、时间及稳定的记录编号组合确定，避免翻页时重复或漏项。

6. 待办与工作进展

   待办最少只需一句话，例如“完成项目 A 的接口联调”。说明、标签、安排日期、截止日期和“重要”标记均可选。没有日期的待办放在“未安排”，不会被强行归到今天。

   | 状态 | 含义 |
   | --- | --- |
   | 待开始 | 还没开始做 |
   | 进行中 | 已经在做，后续还需继续 |
   | 已完成 | 用户明确标记完成，并保留实际完成日期 |
   | 暂缓 | 暂时放下，仍保留以便以后继续 |
   | 已取消 | 已决定不再做，保留原因可选 |

   待办默认展示待开始与进行中，支持今天安排、未安排、已过截止日期、暂缓、已完成等筛选。提示采用“原计划 10 月 25 日，可以调整安排”这类措辞。不会因过期自动取消、算作完成，或每天生成一条重复待办。

   任务详情中提供“记录进展”。例如同一任务周一写“接口已完成”，周二写“联调发现异常”，周三写“修复并验收”。每次进展都是一条发生于当天、关联同一任务的日志；修改任务说明不会覆盖已经写下的工作过程。

   记录进展不自动完成任务。点击完成时默认采用今天，允许补填真实完成日期；如需要，可写一句结果说明。完成操作只更新任务，不自动复制一条内容相同的日志。日视图需要显示完成情况时，从任务读取；当天已有对应进展日志，则在该日志上标出完成状态。

   从日志中的“还有什么要做”可以创建后续待办，预填的标题由用户检查后保存。也可以把日志关联到已有待办。第一版一条进展日志最多关联一个任务，任务可以有多条进展；暂不增加子任务树或项目管理层级。

   “重新打开”恢复任务的未完成状态，清除当前完成日期，原完成动作保留在操作历史中。改计划、延期或取消都不会改写已经发生的工作日志。

7. 数据结构与保存原则

   建议只增加两张业务表。日志表达实际经历，任务表达准备做的事；分开保存，可以让发生日期、计划日期和完成状态各有明确含义。

   | 数据表 | 主要保存内容 | 设计理由 |
   | --- | --- | --- |
   | 生活日志 `zj_journal` | 摘要、正文、分类、起止日期、时间方式、时段或具体时间、地点、人员数组、标签数组、可选任务 ID | 吃饭、上课、出行、工作共用一种记录结构 |
   | 待办任务 `zj_tasks` | 标题、说明、状态、安排日期、截止日期、实际完成日期、结果说明、重要标记、标签数组 | 保存同一项任务的当前状态，不按天复制 |

   两表沿用现有编号、版本、创建时间、更新时间和回收站标记。只在内容实际改变时写更新及审计；重复点击完成、重复保存相同内容不产生无价值版本。

   标签和同行人采用经过校验的 JSON 数组。它们是用户输入，要作为正式业务字段处理，不塞进现有计算结果快照。通用编辑和导出需要补充数组字段支持，让页面使用标签选择器和人员输入框，不要求手写 JSON。

   饭菜、联系人、地点、课程、出差、项目各自不单独建表。常用输入从已有数据查询；固定标签、筛选收藏和页面偏好放入现有设置。统计结果、计算时长、搜索结果、每日占位记录不落库。若以后确实需要维护固定课表或通讯录，再依据新增需求单独设计。

   日期、任务状态、关联任务等常用查询字段建立适用索引；跨日搜索按日期区间相交处理。中文搜索先在现有 MySQL 中使用参数化、正确转义的包含查询，验证单字、短词、空格以及百分号、下划线等输入。暂不增加外部搜索服务，是否优化检索结构由实际数据量和查询表现决定。

8. 与现有工具的衔接

   “数据管理”加入生活日志和待办，支持新增、搜索、编辑、完整查看、移入回收站、恢复和导出。任务移入回收站后，关联的进展日志保留，显示“关联任务已移入回收站”；恢复后重新连接，不级联删除真实经历。

   新数据纳入完整备份和恢复校验。旧备份缺少这两个集合时按空集合处理；同 ID 的合并规则、恢复前备份和现有数据保护继续沿用。CSV 用于导出当前筛选范围；JSON 备份保留数组、关联和原始日期。

   新页面继承本地口令、隐私遮挡、自动锁定和关闭动效设置。与现有烟酒、身体页面共用日期入口时，只读取原记录，不复制它们。写下“聚餐”不会自动新增一笔饮酒；需要记录饮酒量时，仍进入原饮酒表单。

   现有应用启动时会读取注册集合，新模块需要单独提供后端分页和搜索接口，避免多年日志随首页一次性加载。现有烟酒计算读取它需要的集合，生活日志新增、修改不会触发无关的酒精或费用重算。数据管理与备份通过明确入口读取新集合，兼顾日常响应和完整数据管理。

9. 分步实施与交付

   | 阶段 | 交付内容 | 完成标准 |
   | --- | --- | --- |
   | 第一步：日常记录 | 新页面、日历切换、时段记录、快捷模板、跨日事项、日志增删改查 | 能完成吃饭、同行人、上课、工作和出差记录，事后补记日期正确 |
   | 第二步：检索 | 标签输入、关键词搜索、组合筛选、固定入口、结果分页、匹配日期视图 | 一键找到出差日期，按人物或项目回看，跨日命中和去重正确 |
   | 第三步：待办 | 状态、安排与截止日期、工作进展关联、完成与重新打开 | 能回答做了什么、做到哪里、还剩什么，计划与事实不混淆 |
   | 第四步：整体验收 | 数据管理、备份恢复、并发版本保护、界面与原功能回归 | 通过独立测试库验收后，备份正式数据并更新本机版本 |

   上述四步组成第一版完整功能。照片附件、自动识别整段自然语言、固定课表、周期待办、系统通知和外部日历同步留待后续需求；第一版先保证手工记录省事、搜索结果可靠。

10. 验收清单

    | 场景 | 预期结果 |
    | --- | --- |
    | 今天补记上周五晚上和朋友吃饭 | 出现在上周五；按饭菜、朋友姓名、地点均可检索 |
    | 只记“下午修电脑” | 可以保存，不显示伪造的准确时间或持续时长 |
    | 出差持续三天，期间又记录几次聚餐 | 出差事项只保存一条；日期视图三天可查，出差天数去重 |
    | 只安排了下周出差，还没有实际出行 | 显示为待办，不进入实际出差日期 |
    | 任务连续三天分别记录进展 | 任务始终一条，三条实际工作日志可回看 |
    | 完成任务后又重新打开 | 当前状态和完成日期一致，原动作仍可追溯 |
    | 标签改名、合并、移除 | 相关筛选结果同步更新，日志正文和数量不被改坏 |
    | 同名标签有多余空格或重复输入 | 规范化后不重复保存 |
    | 搜索结果超过一页 | 翻页稳定，总数准确，返回保留筛选和位置 |
    | 修改发生日期或将记录移入回收站 | 时间线、搜索和日期统计一起更新；恢复后正确出现 |
    | 两个窗口同时编辑 | 提示版本冲突，不静默覆盖另一处修改 |
    | 反复提交同一次保存或完成 | 不产生重复日志、任务或无变化审计 |
    | 导入旧版备份及新版备份 | 旧数据可用，新日志、任务与关联完整，原有数据受到保护 |
    | 日志达到较大数量 | 日常页面仍按需加载，测量分页和搜索响应后再确定是否需要进一步优化 |

    测试数据只写入独立测试库。正式更新前备份，更新后核对原有烟酒记录、价格、身体数据及设置，确认此次新增功能没有改写它们。
