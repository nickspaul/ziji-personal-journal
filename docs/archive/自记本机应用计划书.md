自记：个人行为与花费记录网站计划书 v0.2

本版采用 Spring Boot、Vue 3 和 MySQL，在本机运行。日常记录、计算和查询均可离线完成；按需联网更新商品资料，个人行为与身体信息保存在本机。第一版完整覆盖吸烟、饮酒、自慰记录，以及商品库、仪表盘、健康说明和数据管理。

1. 应用围绕“记得快、算得清、能回看、可修正”设计。

    吸烟记录根数、具体品牌型号、成本及烟盒标示成分；饮酒记录场次、酒品、瓶数、本人实际饮用毫升、酒精度和费用；自慰记录次数与时间，并自动关联已记录的饮酒情况。

    日常界面默认简洁，详细信息在抽屉中展开。用户可以随时修改名称、记录和目标。提醒以减少烟酒、关注身体感受和生活影响为主，不使用羞辱、恐吓或“破戒归零”的表达。

    本版从桌面浏览器使用出发，同时适配窄屏。默认只允许当前电脑访问；以后如需手机访问同一份数据，再单独增加局域网模式。

2. 首页采用有视觉表现力的仪表盘，同时保留明确的记录入口。

    建议使用深色背景、青蓝与紫色光效、分层卡片和轻量数字动效。提供浅色主题、减少动效和隐私遮挡。颜色搭配文字与图标使用，图表不只靠颜色表达状态。

    | 区域 | 展示内容与操作 |
    |---|---|
    | 顶部 | 日期范围、今日记录完整度、隐私按钮、全局新增 |
    | 快捷记录 | 当前常用香烟“记 1 根”、开始或继续饮酒、记录一次自慰 |
    | 今日概览 | 吸烟根数、饮酒场次、摄入酒液毫升、纯酒精克数、自慰次数 |
    | 花费卡片 | 实际购买支出与个人消耗成本分别展示，可切换周、月 |
    | 趋势图 | 吸烟根数、饮酒量、自慰次数各用自己的单位与图表 |
    | 酒精估算 | 最近饮酒时间、已过时长、模型估算区间及信息完整度 |
    | 行为日历 | 每日记录分布，未记录与确认零次有不同显示 |
    | 时间线 | 三类行为按时间排列，直接查看详情、修改或撤销 |
    | 健康提示 | 当前相关的一条简短说明，可展开查看来源 |

    点击指标能够进入对应明细。图表支持日期筛选、悬停查看和按品牌筛选。首版不设置没有医学依据的“身体健康总分”“肺损伤百分比”或“剩余寿命”。

    导航包括：仪表盘、行为记录、统计分析、商品与价格、购买流水、数据管理、个人设置。健康说明在相关页面内展开，减少来回切换。

3. 快捷记录与详细记录共用同一套数据。

    | 行为 | 常用操作 | 可展开补充的信息 |
    |---|---|---|
    | 吸烟 | 常用品牌一键记 1 根，支持自定义根数 | 实际发生时间、型号、来源、采用价格、情绪、场景、备注 |
    | 饮酒 | 选择常用酒品，点“1 瓶”“半瓶”或填写毫升 | 开始与结束时间、多种酒品、分饮比例、个人付款、场景、备注 |
    | 自慰 | 一键记一次，默认当前时间 | 实际发生时间、时长、前后感受、是否影响休息、备注 |

    时间、最近使用的产品、规格和已确认价格自动带入。品牌未知也可以先保存记录，缺少的价格、酒精度或成分显示“待补充”，不自动当成零。补记时若只记得日期，保存“时间不详”，不编造具体时刻，也不据此进行精确的酒后关联。

    “新增一场饮酒”与“向当前场次追加一杯”分开，避免每续一杯都增加一次饮酒次数。系统可建议合并相邻记录，但由用户确认。

    支持键盘操作、最近记录复用、批量补记、保存后撤销。网络请求重试不能重复插入；连续主动点击记烟则可以记录多根。表单保留草稿，数据库未保存成功时不会显示为完成。

4. 商品资料细化到具体产品与规格，尽量做到选一次后反复复用。

    香烟目录包含品牌、系列、软硬包装等型号信息、每包根数、条盒换算、条码、销售地区，以及烟盒标示成分。酒目录包含品牌、产品名称、类型、瓶或罐容量、酒精度、包装数量和条码。同品牌不同规格分别建档。

    自动补全采用以下顺序：个人常用品、已确认的本地商品库、内置资料、用户主动触发的联网检索。检索支持中文、别名、拼音和条码。常用资料可以收藏，确认过的个人字段允许锁定。

    商品同步优先使用可访问且允许使用的品牌官方资料或公开数据接口；价格按具体规格、地区和渠道保存。实现阶段先验证数据源，再接入适配器。本计划不假定已经存在覆盖全部国产烟酒、价格实时准确的免费接口。

    | 数据 | 自动化方式 | 需要保留的依据 |
    |---|---|---|
    | 品牌、规格、酒精度 | 本地检索、资料导入、按需联网补充 | 来源、规格匹配结果、更新时间、确认状态 |
    | 香烟成分 | 包装标示或可核实的产品资料 | mg/支、包装版本、标示或检测口径、来源图片或链接 |
    | 商品参考价 | 已验证的数据源或本地价格表 | 地区、渠道、币种、采集日期、适用规格 |
    | 个人采用价 | 本次填写、对应购买批次或上次确认价格 | 实际价或参考价的分类、生效时间 |

    同步结果先显示新增项与冲突项，再合并；不能覆盖用户锁定的信息，也不能改变历史记录的价格快照。未知值保持为空。联网请求只发送商品检索所需内容，不附带个人行为、身高体重或备注。

    条码用于匹配商品，不能直接保证得到成交价。普通商品条码通常只是标识符，描述和价格需要到数据库查询。[GS1 条码说明](https://support.gs1.org/support/solutions/articles/43000734158-are-the-description-and-price-of-the-item-included-in-the-barcode-)

    首版提供资料导入、手动补充和联网更新。包装照片、票据的本地文字识别可随后增加；识别结果进入待确认区，不直接当作准确数据入账。

5. 香烟费用分成购买支出和吸烟消耗成本，防止重复计费。

    吸烟记录保存实际时间、根数、产品规格、单根价格快照和价格来源。后端计算：单根价格＝采用的每包价格÷每包根数；本次消耗成本＝根数×单根价格。

    例如，仅作计算示例：一包 20 根，实际购买价 30 元，抽 3 根的消耗成本为 4.50 元。购买流水记录支出 30 元，抽烟记录分摊 4.50 元；两者分别展示，不能相加当成总支出。

    价格采用顺序为本次明确指定价格、关联购买批次的实际单价、适用于记录日期的个人确认价、参考价。使用参考价时标记“估算”；历史日期没有可用价格时保留待补充，不拿今天的价格冒充过去的实际价。

    支持“自购”“别人提供”“其他来源”。别人提供的烟仍计入吸烟根数和成分记录；个人现金支出可以明确记为零，未知价格不能用零代替。可额外显示参考价值，但不混入个人付款。

    调整商品现价不改写过去。纠正历史购买价时，先列出受影响的消耗记录，再执行重算。金额在计算中保留足够精度，汇总后显示到分。

6. 香烟成分与健康说明同时提供，但保留测量含义。

    | 数据项 | 保存方式 | 给用户的说明 |
    |---|---|---|
    | 焦油量 | 包装标示值，mg/支 | 焦油包含致癌物，吸烟会增加癌症和慢性肺部疾病风险 |
    | 烟气烟碱量 | 包装标示值，mg/支；说明烟碱即尼古丁 | 尼古丁会形成依赖，使减少或停止吸烟更困难 |
    | 烟气一氧化碳量 | 包装标示值，mg/支 | 一氧化碳会影响血液携氧，增加心血管负担 |
    | 其他成分 | 有可靠资料时扩展，保存单位及检测方法 | 可介绍烟草特异性亚硝胺、苯、甲醛等的相关危害；无该型号检测值时不填数值 |

    健康说明采用短文加来源，分别解释成分与吸烟整体风险，不将所有危害归给某一种成分。[Cancer Research UK：烟草烟雾中的成分与危害](https://www.cancerresearchuk.org/about-cancer/causes-of-cancer/smoking-and-cancer/whats-in-a-cigarette)

    商品详情展示每支标示值。统计页可以选择查看“包装标示值按根数折算合计”，并始终注明其不是人体吸收量或体内残留量。不同检测口径的数据分开展示；缺资料时显示覆盖根数，不能默认补零。

    低焦油标示不能被解释为更安全，机器测得的烟气产量也不能预测个人实际吸入量。因此系统不按焦油数字推荐“更健康的香烟”，也不推算每抽一根造成的精确器官损伤。[NCI：低焦油香烟与机器测量的局限](https://www.cancer.gov/about-cancer/causes-prevention/risk/tobacco/light-cigarettes-fact-sheet)

7. 饮酒采用“场次＋酒品明细”，同时保留瓶数、毫升和费用。

    一次连续饮酒记为一个场次，场次内可有啤酒、白酒等多条明细。场次记录开始、结束、场景和备注；每条明细记录产品、容量、数量、实际饮用毫升、酒精度快照、饮用时间或区间、价格及付款信息。

    瓶数与毫升互相换算，但只认一份本人实际摄入量：

    - 按整瓶记录：瓶数×每瓶容量。
    - 按部分饮用记录：瓶数×每瓶容量×本人饮用比例。
    - 直接填毫升：以填写的毫升数为准，折合瓶数仅供显示。

    已经由瓶数换算出的毫升，不能再与手填毫升相加。多人分享时区分“开了几瓶”与“自己喝了多少”。不同容量酒品的瓶数分规格展示，汇总以毫升和纯酒精克数为主。

    纯酒精体积＝本人饮用毫升×酒精度百分数÷100；纯酒精质量约等于纯酒精体积×0.789 克/毫升。混饮按每条明细计算后汇总。这个结果是按记录和标签换算的摄入量，不是测得的血液酒精浓度。[酒精换算依据](https://guides.sl.nsw.gov.au/drug-and-alcohol-information-pdhpe/alcohol)

    例如，仅作计算示例：本人喝下 2 瓶 500 毫升、酒精度 5% 的啤酒，合计 1,000 毫升酒液、50 毫升纯酒精，约 39.45 克纯酒精。若每瓶 8 元，对应消耗价值为 16 元；实际个人付款另行记录。

    酒的费用同样区分买酒付款、个人饮用成本和参考价值。整瓶分饮、朋友请客、整单分摊均允许填写。对同一笔付款保留唯一关联，防止在购买流水与饮酒记录中重复入账。

8. 身高体重参与酒精代谢估算，结果以带假设的区间呈现。

    身高体重用于估计酒精在身体中的分布，无法单独决定个人消除速度。酒精代谢还受遗传、营养和药物等因素影响，系统不能保证“某个时间已经完全代谢”。[NIAAA：酒精代谢](https://www.niaaa.nih.gov/publications/alcohol-metabolism)

    实现时采用有文献来源的体水分布模型与酒精浓度估算框架，评估 Watson 与 Widmark 类方法的适用性。模型需要的年龄、生理参数及身体测量由用户明确填写，不根据姓名或行为推断。身高体重按测量日期保存历史；缺少必要参数时仍能记录酒量，但不生成个人化时间预测。

    计算需同时考虑摄入时间、吸收延迟、饮酒过程中已经发生的消除，以及相邻场次的残留叠加。不能把每场独立计算的时长直接相加，也不能一律从最后一杯结束时才开始计算全部消除。

    输出包含：计算所用酒量和身体参数、模型版本、参数假设、估算时间范围、资料缺失项。图表采用区间带，区间是模型情景范围，不是经个人验证的医学置信区间。具体消除速率范围及适用条件在实现前固定出处并记录版本，不能由“自认为酒量好”自动调快。

    界面不提供秒级清零倒计时，不显示“已经清醒”“可以开车”。达到模型计算的接近零值也不能证明实际血液浓度或驾驶能力；饮酒后不要用本工具判断何时能驾驶。[NHTSA：酒精与驾驶能力](https://www.nhtsa.gov/risky-driving/drunk-driving)

    补录或纠正酒量、时间后，自动重算相关区间。新增今天的体重测量不改写过去的计算；明确纠正历史身体参数时，再重算对应时期。

9. 自慰记录自动关联饮酒时间，并允许说明与纠正。

    默认记录发生时间和次数，其余字段选填。保存后在相关饮酒时间线中检查，展示以下状态：

    | 状态 | 含义 |
    |---|---|
    | 饮酒期间 | 发生时间位于已记录的饮酒起止区间内 |
    | 处于估算酒后时段 | 与模型估算时段相交，明确标记为推测 |
    | 有近期饮酒记录，超出模型时段 | 资料足以计算，发生时间在模型时段之外；仍不能确认酒精已经消除 |
    | 近期有饮酒记录，状态不确定 | 时间接近，但酒量、结束时间或模型输入不足 |
    | 未发现对应饮酒记录 | 当前记录中没有匹配项，不能据此证明没有喝酒 |

    “近期”的观察窗口可配置并标注为记录筛选规则，不当作医学安全时限。标签可以展开查看关联场次、时间差和采用的规则。用户可补充“是”“否”“不确定”，自动判断与本人确认分别保留。

    补录前一天的饮酒、修改或删除场次，都要检查受影响的自慰记录；跨午夜正常关联。统计可展示“多少次记录与饮酒时段相邻”，同时列出分母和不确定记录，不能推断饮酒导致了自慰。

10. 提醒采用可调节的语气与频率，避免增加负担。

    提供“只记录”“温和提醒”“主动帮助减少”三种模式，分别设置各行为的提醒强度。用户可暂停提醒、设置安静时段和每日上限；保存记录优先完成，建议不阻断记录。

    | 场景 | 提示文案示例 |
    |---|---|
    | 连续较短间隔吸烟 | “这根已经记下了。如果愿意，下次想抽时可以先等一会儿。” |
    | 接近个人烟酒目标 | “已经接近你设定的本周目标，可以先看看今天是否还想继续。” |
    | 继续追加饮酒 | “这杯已记录。可以考虑到这里结束，给今晚留一些休息时间。” |
    | 记录自慰 | “已记录。想释放一下很正常，也留意自己的舒适程度和休息。” |
    | 记录感受为疲惫或不适 | “先照顾好自己的感受。可以休息一下，再决定是否继续。” |
    | 一段时间没有记录 | “这几天还有空白，方便时再补上就好。” |

    自慰不因次数本身被自动定义为疾病或失败。相关提示关注个人意愿、是否不适，以及是否影响睡眠、工作和生活；不设置没有依据的统一“健康次数”。[Planned Parenthood：自慰与生活影响](https://www.plannedparenthood.org/learn/sex-pleasure-and-sexual-dysfunction/masturbation/masturbation-healthy)

    烟酒目标是用户的行为目标，不标为医学安全线。健康资料与个人提醒分开：资料保留来源和更新日期，提醒使用本地规则生成，第一版不依赖在线聊天模型。

11. 内置数据管理台，覆盖每一条业务数据。

    管理台提供表格筛选、搜索、排序、分页、详情、新增、修改、删除、批量操作、导入导出和回收站。可以查看字段名称、关联对象、采用的价格与计算依据。

    | 数据范围 | 管理能力 |
    |---|---|
    | 三类行为与饮酒明细 | 逐条增删改查，支持补记、拆分或合并饮酒场次 |
    | 商品、规格、别名、成分 | 增删改查、停用、重复项合并、资料来源维护 |
    | 参考价、个人价格、购买流水 | 修改与历史查询，查看受影响的成本记录 |
    | 身体参数、目标、提醒、标签 | 增删改查及生效时间管理 |
    | 健康说明和资料来源 | 查看与维护，用户笔记与原始来源内容分开 |
    | 估算结果、酒后关联 | 查看输入和版本、重新计算、保存带理由的人工更正 |
    | 导入任务、备份和操作历史 | 查看结果、失败原因、恢复点及清理记录 |

    用户输入的数据可编辑；金额合计、纯酒精量等派生结果通过修改来源数据重算。需要人工覆盖的字段同时保存自动值与覆盖理由，避免统计在表面上对不上。

    删除有历史引用的商品时优先停用，保留当时的名称、规格、成分和价格快照。批量修改先展示影响范围，多个相关变更一起成功或一起回滚。日常删除进入回收站，支持恢复；永久清除有独立入口。

    所有业务页面与管理台共用后端校验和计算规则。操作历史默认只读，支持按保留期限清理；数据库迁移版本等系统记录由维护功能管理，不开放成普通业务表随意改写。这有助于排查错误，但不能宣称本机数据库管理员无法修改日志。

12. 技术结构采用模块化单体，减少本机运行的维护负担。

    | 层次 | 方案与责任 |
    |---|---|
    | 前端 | Vue 3、TypeScript、Vite；路由、状态管理、记录抽屉和管理表格 |
    | 图表 | Apache ECharts，绘制趋势、日历热力图、费用分布与估算区间 |
    | 后端 | Spring Boot，按记录、商品、费用、计算、统计和管理划分模块 |
    | 数据库 | MySQL，持久保存业务数据、快照、关系与来源 |
    | 本地文件 | 商品资料图片、导入文件、导出结果和备份清单 |
    | 外部数据 | 独立商品资料适配器，按需联网，失败不影响本地记录 |

    Vue 支持 TypeScript，ECharts 提供多种图表与交互能力；具体依赖版本在开发前与本机环境匹配，不预设必须升级已有环境。[Vue 官方文档](https://vuejs.org/guide/typescript/overview.html)、[ECharts 官方介绍](https://echarts.apache.org/en/index.html)

    正式使用时把前端构建结果交由 Spring Boot 提供，通过一个本地地址访问；开发时允许前后端分别启动。[Spring Boot 静态资源支持](https://docs.spring.io/spring-boot/reference/web/servlet.html)

    后端负责最终校验与计算，前端只做即时预览。金额使用 Java BigDecimal 和 MySQL DECIMAL；根数用整数，容量与酒精度支持小数。数据库保留明确单位，日期按 Asia/Shanghai 展示，并保存实际发生时间与录入时间。[MySQL 精确数值类型](https://dev.mysql.com/doc/refman/8.4/en/fixed-point-types.html)

    关键写入使用事务；对重复提交、导入去重和多窗口编辑冲突进行检查。变更后重算相关统计和关联，失败时明确标记待重算。数据库结构采用版本化迁移，升级前保留备份。

13. 数据库将事实记录、商品资料和计算结果分开保存。

    | 数据表或表组 | 关键内容 |
    |---|---|
    | profile、body_measurement | 本地用户设置、身高体重与模型所需参数的历史 |
    | product、product_variant、product_alias | 品牌、具体产品、容量或根数、条码和别名 |
    | tobacco_constituent | 成分名、mg/支、标示或检测方法、包装版本与来源 |
    | product_price | 参考价与个人采用价、单位、地区、渠道、生效时间、确认状态 |
    | purchase、purchase_item | 实际购买时间、数量、金额、付款人及具体批次 |
    | consumption_allocation | 某次吸烟或饮酒对应哪个购买批次、分摊多少成本 |
    | smoking_record | 时间、根数、规格、价格与成分快照、来源、备注 |
    | drinking_session | 场次起止时间、场景、状态及完整度 |
    | drinking_item | 场次内各酒品、本人饮用量、ABV 快照、饮用时间、费用 |
    | masturbation_record | 时间、次数、选填感受、本人确认的酒后状态 |
    | alcohol_estimate、behavior_link | 模型输入快照、版本、区间、关联依据和人工更正 |
    | daily_completeness | 按日期与行为确认是否完整、是否明确为零 |
    | goal、reminder_rule | 个人目标、提示条件、语气、安静时段 |
    | health_knowledge、data_source | 健康说明、商品资料出处、更新时间与版本 |
    | attachment、import_job、backup_manifest | 本地附件、导入结果、备份内容与版本信息 |
    | change_log | 修改时间、对象、前后值、修改来源 |

    原始记录保存单位、版本、来源和必要快照；派生结果可重新计算。每条业务记录带创建、修改时间及删除状态，重要关系使用外键或等效约束。目录更新、身体参数新增和历史纠错采用不同的重算规则。

14. 统计保留记录完整度，让数字有明确含义。

    吸烟按根数统计，饮酒分别按场次、发生天数、毫升和纯酒精克数统计，自慰按次数统计。费用同时保留“实际支出”“已知消耗成本”“待补价格记录数”。成分折算显示资料覆盖范围。

    未记录、已记录但未确认完整、确认完整且为零是不同状态。周月比较同时展示确认天数；资料不足时展示已知总量，不输出容易被误读为改善的下降百分比。连续未发生天数只在确认完整的日期上累计。

    跨午夜的饮酒仍可是一场，场次按开始日期归属；摄入量按明细的实际时间归属。只有总量而没有分时明细时，注明归属规则，避免制造精确到小时的假象。

15. 本机运行需要配套启动、备份与隐私管理。

    应用默认仅绑定 127.0.0.1，MySQL 使用本机专用账号，浏览器不直接连接数据库。数据库凭据只留在后端本地配置。首次设置本地解锁口令，敏感页面支持自动锁定；隐藏名称与数字只是显示遮挡，不能代替访问控制。

    后端检查会话和请求来源。脚本、字体与图表资源随应用提供，日常运行不依赖外部 CDN，不接入广告与行为追踪。同步商品资料失败时提示原因并继续使用现有目录。

    提供 Windows 本地启动与停止入口，启动时检查端口和数据库连接。应用关闭或电脑关机时不承诺提醒，重新打开后按实际时间恢复计算和提示。

    备份覆盖数据库、附件和版本清单，支持手动及运行期间的定期备份。恢复前校验文件并备份当前状态，先预览再恢复。导入支持重复检查与错误行报告。全部个人资料的永久清除覆盖业务记录、操作历史中的前后值、计算输入快照、附件和草稿；已经导出的文件及历史备份需要单独处理。

16. 按可验收的阶段交付，第一版包含本次明确提出的功能。

    | 阶段 | 交付内容 | 通过条件 |
    |---|---|---|
    | 1. 数据与原型 | 数据字典、计费规则、仪表盘和快速记录原型 | 根数、瓶数、毫升、价格和状态含义明确 |
    | 2. 基础记录 | 三类记录、产品规格、价格、购买流水、数据管理 | 记录可增删改查，重启后数据保留，费用不重复 |
    | 3. 自动计算 | 成分折算、纯酒精量、代谢估算、酒后关联 | 混饮、共享、跨日和补录结果正确，缺资料不伪造结果 |
    | 4. 完整界面 | 仪表盘、筛选分析、隐私显示、温和提示 | 指标可追溯到明细，提醒可关闭，操作保持快捷 |
    | 5. 商品更新与交付 | 验证后的资料源、导入导出、备份恢复、本地启动 | 断网可记录，更新不覆盖历史，备份可恢复 |

    验收重点包括：同品牌不同规格不混用；瓶数与毫升不重复累计；朋友提供与未知价格可区分；历史价格更新不改变既有账目；补记饮酒会更新关联；撤销和删除同步更新统计；成分标示值不被显示为人体吸收量；模型信息不足时停止给出个人化时长；商品联网请求不携带个人信息。

    后续增强可包括本地票据识别、条码摄像头识别、更完整的库存和经明确开启的局域网访问。身高体重、常用烟酒型号和提醒强度在首次设置中填写；这些个人数值无需在计划阶段提供。
